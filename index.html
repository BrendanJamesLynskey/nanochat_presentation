Part 1

What is nanochat?

One repo, the entire ChatGPT pipeline, ~$100

"The best ChatGPT that $100 can buy"

The pitch: boot a single 8×H100 GPU node, run one script, and ~4 hours later you have a small ChatGPT clone you can talk to in a web UI. At ~$24/hr for the node, that is roughly $100.

The point: not to compete with frontier models, but to make the entire stack — tokeniser to served chat model — legible, minimal, and forkable in one place.

Part 2

The Tokeniser

A custom, fast BPE tokeniser trained on the data

Train Your Own BPE

# Download ~2B characters of pretraining text (≈8 shards)
python -m nanochat.dataset -n 8

# Train a byte-level BPE tokeniser on that text
python -m scripts.tok_train      # vocab default 2**15 = 32,768

# Evaluate it (compression ratio vs. references)
python -m scripts.tok_eval

Why a custom tokeniser? A BPE vocabulary trained on the same distribution it will model compresses that text more efficiently — fewer tokens per document means more learning per FLOP. nanochat trains its own rather than borrowing GPT-2's.

Fast by Design — a Rust BPE

Rust implementation: training a BPE over ~2B characters is heavy, so nanochat wraps a fast Rust BPE trainer (RustBPETokenizer), in the style of GPT-4's tokeniser, rather than a slow pure-Python loop.

Vocabulary size: a power of two — 2¹⁵ = 32,768 on current master (the original $100 d20 run used 2¹⁶ = 65,536).

Part 3

Base Pretraining

Training the transformer — one dial: --depth

The Depth Dial

# Pretrain the base model across 8 GPUs.
# --depth is the ONE complexity dial you set.
torchrun --standalone --nproc_per_node=8 \
    -m scripts.base_train -- --depth=20 --run=$WANDB_RUN

# GPT-2 grade capability sits around depth 24-26.

One integer sets everything. From --depth alone, nanochat computes the width, number of heads, learning-rate schedule, training horizon and weight decay — automatically, in a compute-optimal way. You ask for a bigger or smaller model; you don't hand-tune a wall of hyperparameters.

Sweeping depth (d12, d16, d20, d24, d26) gives the nanochat "miniseries" of compute-optimal models. The $100 speedrun is a d20.

Architecture Choices

Rotary embeddings
no learned pos.
Positions come from RoPE applied to Q and K — no separate position-embedding table
RMSNorm
no learned params
Parameter-free RMS normalisation in place of LayerNorm — simpler and stable
ReLU² MLP
squared ReLU
The MLP activation is relu(x)², a strong modern choice over plain ReLU/GELU
GQA · untied
efficient infer.
Group-Query Attention for cheaper KV cache; token embedding and lm_head are untied

The optimiser is a mixed Muon + AdamW: matrix parameters go through Muon, embeddings and scalars through AdamW. Precision is managed explicitly via a single COMPUTE_DTYPE (bf16 on H100), not autocast.

The CORE Metric

How do we know the base model is any good? nanochat reports the DCLM CORE score — an aggregate over many standard language-understanding tasks — plus val_bpb (validation loss in vocab-invariant bits per byte).

The public leaderboard races the wall-clock time to push CORE above GPT-2's 0.2565 on an 8×H100 node — currently down to under ~1.7 hours.

Part 4

Midtraining & SFT

Turning a text predictor into a chat assistant

The Chat Format

Midtraining first teaches the model the structure of a conversation via special tokens:

<|user_start|> Why is the sky blue? <|user_end|> <|assistant_start|> Sunlight scatters off air molecules, and shorter (blue) wavelengths scatter most… <|python_start|> print(2 + 2) <|python_end|> <|assistant_end|>

The purple tokens delimit turns; the green tokens let the model call a Python interpreter as a tool. These are learned during midtraining, not bolted on at inference time.

Midtraining → SFT

# Midtraining: adapt the base model to conversations,
# multiple-choice (MMLU-style) and Python tool use.
torchrun --standalone --nproc_per_node=8 -m scripts.mid_train

# SFT: supervised fine-tuning on curated conversations
torchrun --standalone --nproc_per_node=8 -m scripts.chat_sft
torchrun --standalone --nproc_per_node=8 -m scripts.chat_eval -- -i sft

Midtraining (~8 min) is broad and cheap: it mixes conversational data, multiple-choice questions, and tool-use traces so the model learns the chat format. SFT (~7 min) then refines on higher-quality conversations (e.g. HuggingFace's SmolTalk) with proper sequence padding, sharpening response quality.

Part 5

Optional RL

Squeezing out more on a verifiable task

RL on GSM8K via "GRPO"

# Reinforcement learning on grade-school maths,
# where answers can be checked automatically.
torchrun --standalone --nproc_per_node=8 \
    -m scripts.chat_rl -- --run=$WANDB_RUN

Why GSM8K? Maths answers are verifiable — you can score a rollout as right or wrong with no human or reward model. That makes it the natural target for RL in a minimal repo.

"GRPO" (in quotes): nanochat's variant samples a group of answers per question and uses the reward minus the group mean as the advantage — dropping the z-score division (no σ normalisation) of textbook GRPO. Simpler, and it works here.

What RL Adds Beyond SFT

SFT imitates demonstrations; RL optimises an outcome. Instead of copying a reference answer, the model explores its own solution paths and is rewarded for ones that reach the correct result — directly improving the metric it is graded on.

It is the optional final squeeze: not part of the core ~$100 chat pipeline, and it adds significant wall-clock time (~1.5 hours), but it demonstrates the last rung of the modern post-training ladder inside the same tiny codebase.

Part 6

Serve & the Speedrun

Talk to it — and scale the dollar budget

A ChatGPT-Style Web UI

# Serve your model in a familiar chat web app
python -m scripts.chat_web
#  → visit http://<node-ip>:8000/

# ...or talk to it on the command line
python -m scripts.chat_cli -p "Why is the sky blue?"

Engine + UI: nanochat/engine.py provides efficient inference with a KV cache; scripts/chat_web.py serves a minimal HTML/CSS/JS chat front-end. The model you trained four hours ago is now a chatbot in your browser — ask it for a poem, or watch it confidently hallucinate who you are.

Scaling the Budget

How speedrun.sh Stitches It Together

python -m nanochat.report reset       # start the report card
python -m nanochat.dataset -n 8        # download text for the tokeniser
python -m scripts.tok_train            # train the BPE tokeniser
torchrun ... -m scripts.base_train     # pretrain the base model
torchrun ... -m scripts.base_eval      # CORE / bpb / samples
torchrun ... -m scripts.chat_sft       # midtrain + SFT to a chat model
torchrun ... -m scripts.chat_eval      # ARC / MMLU / GSM8K / HumanEval
python -m nanochat.report generate     # assemble the final report.md

Every stage writes a section to the report; the last command assembles them. Boot a node, run one line, come back to a trained, evaluated, serveable ChatGPT clone — and a scorecard.

1

The whole pipeline is graspable. Tokeniser → pretrain → midtrain → SFT → RL → eval → serve fits in one ~8,300-line, dependency-light, hackable repo you can read end to end.
